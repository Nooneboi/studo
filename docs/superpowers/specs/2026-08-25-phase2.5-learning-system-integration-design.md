# Phase 2.5 Learning System Integration Design

## Goal

Make Alpha 18's learner-facing systems behave like one coherent learning product before expanding more Reading content.

## Approved product rules

- Practice teaches. Train strengthens. Mock measures.
- Progress must return learners to the canonical curriculum/skill experience, not the retired category detour.
- A brand-new learner should be directed to Practice before Train pretends to personalize.
- Guided Practice should lead naturally to the next Independent Practice when one exists.
- While Mock uses the temporary Practice-bank fallback, learner-facing copy must describe it as format/timing practice rather than an independent readiness simulation.
- Unavailable future subjects should stay hidden in the learner-facing alpha.
- Home should explain Practice, Train, and Mock in plain learner language.
- Keep current content, PDFs, mastery weighting, delivery-role separation, and Mock exclusion behavior intact.
- Do not create new Skill Checks, Mock-only items, PDFs, or content in this phase.
- Do not enforce `release-gate.json` in deployment in this phase; changing live deployment policy is a separate operational decision.

## Architecture

Add a small shared browser helper, `js/curriculum-routes.js`, that derives canonical learner destinations from `data/generated/curriculum.json`. Progress uses it to map skill IDs to current skill/unit pages, and Module completion uses it to find the next practice set on the same skill/unit page.

Train keeps the existing adaptive engine, but the learner UI blocks automatic training when there are fewer than three recorded attempts. This preserves the current `Learning.buildTrainingPlan()` behavior for established learners while making the new-user experience honest.

Copy/UI changes stay local to the learner surfaces that own them: `quiz.html`/`js/test.js` for Mock wording, `js/app.js` for the subject bar, and `index.html` for Home explanations.

## Success criteria

1. Progress contains no learner route to `category.html` for skill recommendations or skill rows.
2. Skill IDs in Progress resolve to `skill.html?...&skill=` or `skill.html?...&unit=` using the generated curriculum.
3. With fewer than three attempts, Train presents Practice as the primary next action and does not start an automatic baseline session.
4. After a Guided module, completion offers the next Independent Practice directly when the same curriculum item has a later set.
5. Mock landing/result labels do not call Practice-fallback mode a full/exam simulation or independent readiness measure.
6. Learner subject navigation shows only RLA while future subjects remain inactive internally.
7. Home explains Practice, Train, and Mock directly.
8. Existing full tests, content validation, content build, public build, release counts, and broken-reference checks remain green.
